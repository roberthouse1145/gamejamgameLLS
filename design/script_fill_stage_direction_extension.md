# script_fill 重构：整页剧本 + 舞台指示扩展

## 1. 现状问题

当前 script_fill 的 UI 是"多张卡片"布局：

```
┌ Slot 1 ──────────┐  ┌ Slot 2 ──────────┐  ┌ Slot 3 ──────────┐
│ 几行上下文         │  │ 几行上下文         │  │ 几行上下文         │
│ <<<FILL>>>        │  │ <<<FILL>>>        │  │ <<<FILL>>>        │
│ 几行上下文         │  │ 几行上下文         │  │ 几行上下文         │
│ [建议1][建议2]     │  │ [建议1][建议2]     │  │ [建议1][建议2]     │
└───────────────────┘  └───────────────────┘  └───────────────────┘
```

问题：
- 一场戏被拆成 3-5 个孤立片段，**剧本的连贯感被打碎**
- 每个 slot 重复几行上下文营造"前后文感"，但实际上是人为制造的冗余
- 玩家看到的不是"一页剧本"，而是"一堆考题"

## 2. 目标

改成**一页完整剧本**，空位直接嵌在行文中：

```
┌─ 第三幕 · 天台争执 ─────────────────────────────────────────┐
│                                                              │
│  天台的门被风吹得咣咣响，少女站在门口没有动。                    │
│  少女：「你是不是又想一个人扛？」                                │
│  少年背对着她，手撑在栏杆上。                                   │
│                                                              │
│  少年：「____________」  ← 空位 1（台词）                      │
│    · 我就透透气，你至于吗。                                     │
│    · ……好吧，这次算我的错。                                    │
│                                                              │
│  少女没有接话。风从两人之间穿过，卷起她的发梢。                   │
│  少年低声说了什么，她没听清。                                    │
│                                                              │
│  ▸ 少女 ____________  ← 空位 2（舞台指示）                    │
│    · 走近一步，语气突然变软                                     │
│    · 攥紧了拳头，指甲掐进掌心                                   │
│                                                              │
│  少女：「……我就是觉得，你至少可以说一声。」                      │
│  她的声音很轻，几乎被风吹散。                                   │
│                                                              │
│  少年：「____________」  ← 空位 3（台词）                      │
│    · 等一下，我话还没说完。                                     │
│    · ……下次我会说一声的。                                      │
│                                                              │
│  少女听到他的声音，停下了脚步，但没有回头。                       │
│  远处传来放学的铃声。                                          │
│                                                              │
└──────────────────────────────────────────────────────────────┘
                                         已完成 2/3  [ 提交 ]
```

核心变化：
- **没有 slot 的概念了**。只有一个"scene"——一整段连贯的剧本
- **空位是剧本中的洞**，台词空位和舞台指示空位自然交织
- **上下文不再重复**——每一行只出现一次，空位前后就是真实的剧本上下文
- **阅读体验像稿纸**，不像答题卡

## 3. 数据模型变化

### 3.1 旧模型（多 slot）

```
scene_brief: "..."
slots: [
    { speaker, hint, blocks: [narration, dialogue, blank, dialogue], suggestions },
    { speaker, hint, blocks: [...], suggestions },
    { speaker, hint, blocks: [...], suggestions },
]
```

### 3.2 新模型（单 scene，多 blank）

```
scene_brief: "第三幕 · 天台争执"
blocks: [
    { type: "narration", text: "天台的门被风吹得咣咣响..." },
    { type: "dialogue", speaker: "少女", text: "你是不是又想一个人扛？" },
    { type: "narration", text: "少年背对着她，手撑在栏杆上。" },
    { type: "blank", speaker: "少年", hint: "顶嘴/心软/沉默", suggestions: [...] },
    { type: "narration", text: "少女没有接话。风从两人之间穿过..." },
    { type: "stage_blank", target: "少女", hint: "此时少女的反应", suggestions: [...] },
    { type: "dialogue", speaker: "少女", text: "……我就是觉得，你至少可以说一声。" },
    { type: "narration", text: "她的声音很轻，几乎被风吹散。" },
    { type: "blank", speaker: "少年", hint: "追上去/嘴硬/认真道歉", suggestions: [...] },
    { type: "narration", text: "少女听到他的声音，停下了脚步，但没有回头。" },
]
```

关键区别：
- **顶层是 `blocks` 数组**（不是 `slots` 数组包裹 `blocks` 数组）
- `blank` 和 `stage_blank` 直接散布在 blocks 流中，自带 `suggestions`
- 不再有 slot 层级的 `speaker` / `hint` / `blocks` 嵌套

### 3.3 block 类型一览

| type | 说明 | 可交互 | 字段 |
|---|---|---|---|
| `narration` | 旁白/环境描写 | 只读 | `text` |
| `dialogue` | 角色对白 | 只读 | `speaker`, `text` |
| `stage_direction` | 舞台指示（角色动作） | 只读 | `text`, `target`（可选） |
| `blank` | 台词空位 | 可填写 | `speaker`, `hint`, `suggestions` |
| `stage_blank` | 舞台指示空位 | 可填写 | `target`, `hint`, `suggestions` |

## 4. DSL 格式变化

### 4.1 旧格式

```
scene_brief: ...
@slot 角色 | hint
正文...
角色：<<<FILL>>>
@suggestions
...
@end

@slot 角色 | hint
...
@end
```

### 4.2 新格式

不再有 `@slot ... @end` 容器。整个 DSL 就是一段连续的剧本，空位标记和建议直接内嵌：

```
scene_brief: 第三幕 · 天台争执

天台的门被风吹得咣咣响，少女站在门口没有动。
少女：「你是不是又想一个人扛？」
少年背对着她，手撑在栏杆上。

少年：<<<FILL | 顶嘴 / 心软 / 沉默>>>
@suggestions
- 我就透透气，你至于吗。
- ……好吧，这次算我的错。
- 我没打算走远，别紧张。
@end

少女没有接话。风从两人之间穿过，卷起她的发梢。
少年低声说了什么，她没听清。

[少女 · STAGE_FILL | 此时少女的反应]
@suggestions
- 走近一步，语气突然变软
- 攥紧了拳头，指甲掐进掌心
- 偏过头去，不想让他看到自己的表情
@end

少女：「……我就是觉得，你至少可以说一声。」
她的声音很轻，几乎被风吹散。

少年：<<<FILL | 追上去 / 嘴硬 / 认真道歉>>>
@suggestions
- 等一下，我话还没说完。
- 你怎么每次都自己走了。
- ……下次我会说一声的。
@end

少女听到他的声音，停下了脚步，但没有回头。
远处传来放学的铃声。
```

### 4.3 格式规则

- `scene_brief: ...` — 场景标题/摘要（第一行）
- 普通行 — 旁白
- `角色名：「...」` 或 `角色名：...` — 对白
- `角色名：<<<FILL>>>` 或 `角色名：<<<FILL | hint>>>` — 台词空位
- `[角色名 · STAGE_FILL]` 或 `[角色名 · STAGE_FILL | hint]` — 舞台指示空位
- `@suggestions ... @end` — 紧跟空位之后的建议列表
- 空行 — 段落分隔（UI 上渲染为间距）
- 不再需要 `@slot` 和匹配的 `@end`

## 5. UI 变化

### 5.1 整体布局

从"卡片列表"改为"滚动剧本页"：

```
┌─ 场景标题 ──────────────────────────────────┐
│  第三幕 · 天台争执                            │
├─────────────────────────────────────────────┤
│                                              │
│  旁白行（只读，淡色）                          │
│  对白行（只读，深色，带角色名）                 │
│  ...                                         │
│  ┌─ 台词空位 ────────────────────────────┐   │
│  │  少年：「[____________]」              │   │
│  │  · 建议 1                             │   │
│  │  · 建议 2                             │   │
│  │  · 建议 3                             │   │
│  └────────────────────────────────────────┘  │
│  旁白行（只读）                               │
│  ...                                         │
│  ┌─ 舞台指示空位 ────────────────────────┐   │
│  │  🎬 少女 [____________]               │   │
│  │  · 建议 1                             │   │
│  │  · 建议 2                             │   │
│  └────────────────────────────────────────┘  │
│  对白行（只读）                               │
│  ...                                         │
│                                              │
├─────────────────────────────────────────────┤
│  已完成 2/3              [ 提交 ]            │
└─────────────────────────────────────────────┘
```

### 5.2 只读行渲染

- **旁白**：浅灰色文字，正常字重
- **对白**：`角色名：「台词」`，角色名粗体+主题色，台词深色
- **舞台指示（只读）**：斜体 + `▸` 前缀 + 淡灰色，视觉上比旁白更轻

### 5.3 可交互空位渲染

空位用一个轻微高亮的区块包裹，和周围只读行在视觉上有明显区分：

- **台词空位**：带角色名 + 引号框 + LineEdit + 下方建议按钮
- **舞台指示空位**：🎬 前缀 + LineEdit + 下方建议按钮，底色偏蓝区分

空位区块不是独立卡片，而是**嵌在剧本流中的内联区域**——上下文自然衔接，不需要额外的"上文/下文"展示。

## 6. 数据流

### 6.1 提交

```gdscript
# 每个空位的填写结果
{
    "blank_index": 0,           # 第几个空位（从 0 开始）
    "type": "blank",            # 或 "stage_blank"
    "speaker": "少年",           # blank 时为说话人，stage_blank 时为 target
    "player_line": "……好吧，这次算我的错。",
}
```

### 6.2 creative_prompt

`_build_creative_prompt()` 遍历整个 blocks 流，把所有行（包括玩家填入的内容）拼成一段完整的剧本文本：

```
场景摘要：第三幕 · 天台争执

天台的门被风吹得咣咣响，少女站在门口没有动。
少女：「你是不是又想一个人扛？」
少年背对着她，手撑在栏杆上。
少年：「……好吧，这次算我的错。」
少女没有接话。风从两人之间穿过，卷起她的发梢。
[少女走近一步，语气突然变软]
少女：「……我就是觉得，你至少可以说一声。」
她的声音很轻，几乎被风吹散。
少年：「……下次我会说一声的。」
少女听到他的声音，停下了脚步，但没有回头。
远处传来放学的铃声。
```

只有一段完整文本，不再是"片段 1 / 片段 2 / 片段 3"的拼接。

### 6.3 工单

DevCycleManager 完全不需要改——creative_prompt 仍是纯文本字符串。

## 7. 实现影响评估

### 7.1 需要改的

| 模块 | 改动量 | 说明 |
|---|---|---|
| DSL parser (`minigame_content_service.gd`) | **大** | 从"解析 @slot...@end 容器"改为"逐行解析连续剧本流"。新增 `STAGE_FILL` 识别。输出从 `{slots: [...]}` 改为 `{blocks: [...]}` |
| UI (`script_fill.gd`) | **大** | 从"每个 slot 一张卡片"改为"连续滚动的剧本页"。渲染逻辑从 `for slot in slots` 改为 `for block in blocks`。新增 `stage_direction` 和 `stage_blank` 渲染 |
| `_build_creative_prompt()` | 小 | 从"逐 slot 拼接"改为"逐 block 拼接成一段完整文本" |
| `_compose_slot_script()` | 删除 | 不再有 slot，替换为 `_compose_full_script()` |
| LLM prompts | 中 | instructions 和 schema 更新为新 DSL 格式 |
| fallback content | 小 | 从 `{slots: [...]}` 改为 `{blocks: [...]}` |

### 7.2 不需要改的

| 模块 | 原因 |
|---|---|
| `minigame_base.gd` | 只关心 `finish(result)`，不碰内容结构 |
| `MinigameManager` | review 文案走 `review_type_desc` 注入，不碰内容 |
| `DevCycleManager` | creative_prompt 是纯文本，不碰结构 |
| review 链路 | 仍然是"提交时把填好的文本发给 LLM 审核"，逻辑不变 |

## 8. 迁移策略

### Phase 1：结构迁移（slot → scene blocks）
1. 新 DSL 格式（去掉 `@slot`，改为连续流）
2. 新 parser（逐行解析，输出 flat `blocks` 数组）
3. 新 UI（连续剧本页）
4. 新 `_build_creative_prompt()`

### Phase 2：舞台指示
1. 新增 `stage_direction` 只读 block
2. 新增 `stage_blank` 可交互 block + `[STAGE_FILL]` 解析
3. 更新 LLM prompts 让生成内容包含舞台指示空位

Phase 1 和 Phase 2 可以**不分开做** —— 既然要重写 parser 和 UI，不如一步到位。

## 9. 向后兼容

旧的 `@slot ... @end` 格式可以在 parser 中保留识别能力（遇到 @slot 就按旧逻辑兜底），但新的 LLM prompt 只生成新格式。这样测试数据和 fallback 不会立刻失效。
