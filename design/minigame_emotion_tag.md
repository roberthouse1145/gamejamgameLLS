# 情绪标注小游戏（emotion_tag）设计文档

## 1. 概述

| 属性 | 值 |
|---|---|
| 类型 | 氛围型（不产出实质 AVG 内容） |
| 时长 | 60-90 秒 |
| 输入方式 | 点击/拖拽（纯选择，无文字输入） |
| 触发时机 | DevWork 工作时段，出现"情绪/氛围调试"类任务时 |
| 数值影响 | quality（质量）微调 + 林夏好感微调 |

## 2. 体验定位

**"你正在给角色的情绪演出做调试"**

AVG 的灵魂不是台词本身，而是每句话背后的情绪演出。这个小游戏模拟玩家以"演出调试员"身份，快速判断一批台词的情感基调。

**不是创作，是判断** —— 和 script_fill "你来写台词" 完全互补。

## 3. 玩法

### 3.1 核心循环

```
┌─ 情绪标注面板 ────────────────────────────────┐
│                                               │
│  📄 Scene: 第二章·学院走廊                      │
│                                               │
│  ┌─────────────────────────────────────────┐  │
│  │ "你为什么每次都这样？"                     │  │
│  │                — 赛琳                     │  │
│  └─────────────────────────────────────────┘  │
│                                               │
│  这句台词的情绪是？                             │
│                                               │
│  ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐         │
│  │ 愤怒 │ │委屈 │ │担忧 │ │冷淡 │ │期待 │         │
│  └────┘ └────┘ └────┘ └────┘ └────┘         │
│                                               │
│  进度: ▓▓▓▓▓░░░░░  5/10                      │
│  连续命中: 🔥 3                                │
└───────────────────────────────────────────────┘
```

### 3.2 流程

1. 系统从项目 KnowledgeBase 或当前剧情上下文中提取 **8-12 句台词/旁白**
2. 每句配有一个**预设正确情绪**（由 LLM 在生成素材时标注）
3. 台词逐句展示，每句给出 **4-5 个情绪标签**供选择
4. 玩家点击认为正确的标签
5. 反馈：
   - ✅ 命中 → 标签亮起 + 轻微粒子效果 + 连击计数
   - ❌ 偏差 → 标签变灰 + 显示正确答案（"林夏觉得这里更像是「委屈」"）
6. 全部完成 → 结算面板

### 3.3 节奏设计

| 元素 | 设计 |
|---|---|
| **每句判断时间** | 无硬性限时，但有渐变催促动画（5 秒后台词开始淡出）|
| **连击机制** | 连续命中 3/5/8 次触发"调试之眼"/"完美共鸣"等反馈词 |
| **容错** | 没有失败条件，只有分数高低 |
| **干扰项** | 5 个标签中 1-2 个是明显不相关的（降低难度），1 个是"近义迷惑项"（增加趣味）|

## 4. 素材生成

### 4.1 来源

小游戏素材（台词 + 正确情绪标签）由 **LLM 实时生成**：

1. LLM 接收当前项目 KB（世界观、角色设定、剧情进度）作为上下文
2. 一次性生成 8-12 句**符合项目风格的虚拟台词**，每句附带正确情绪标签和 4 个干扰项
3. 这些句子**不需要是 AVG 中实际使用的台词**——只要风格和角色一致即可（氛围型，内容不落地）
4. **Fallback**：如果 LLM 生成失败，使用预制的通用台词+情绪对

### 4.2 生成链路

- 走 `MinigameContentService` 的标准链路（和 script_fill 一样）
- `_is_generated_minigame_type()` 需要新增 `"emotion_tag"` 判断
- prompt 模板让 LLM 输出结构化数据（JSON 或简单 DSL）

### 4.3 生成 Prompt 示例

```
你是一个 AVG 情绪设计师。根据以下项目背景，生成 10 句台词/旁白，每句标注正确情绪和 4 个干扰项。

【项目背景】
{{knowledge_base_context}}

【当前角色】
{{character_profiles}}

要求：
- 每句台词 10-30 字，像真实 AVG 剧本中的一句话
- 角色台词需标注说话人
- 旁白无需标注说话人
- 正确情绪从以下词库中选：[期待, 欣喜, 感激, 安心, 骄傲, 愤怒, 委屈, 绝望, 恐惧, 焦虑, 冷淡, 犹豫, 困惑, 释然, 倦怠, 强颜欢笑, 口是心非, 故作镇定]
- 干扰项同样从词库中选，其中 1 个应为近义迷惑项
- 10 句中覆盖至少 5 种不同情绪

输出格式（每行一句）：
speaker|line|correct_emotion|option1,option2,option3,option4
```

### 4.4 解析后的数据结构

```gdscript
# 每道题目
{
    "line": "你为什么每次都这样？",
    "speaker": "赛琳",
    "correct_emotion": "委屈",
    "options": ["愤怒", "委屈", "担忧", "冷淡", "期待"],
}
```

### 4.5 情绪词库

基础情绪池（可扩展）：

| 大类 | 具体标签 |
|---|---|
| 正面 | 期待、欣喜、感激、安心、骄傲 |
| 负面 | 愤怒、委屈、绝望、恐惧、焦虑 |
| 中性 | 冷淡、犹豫、困惑、释然、倦怠 |
| 复合 | 强颜欢笑、口是心非、故作镇定 |

每道题从词库中抽取 4-5 个，确保：
- 1 个正确答案
- 1-2 个近义迷惑项（如"愤怒"和"委屈"在某些语境下都说得通）
- 1-2 个明显无关项

## 5. result 字段

```gdscript
{
    "score": 0.8,           # 命中率
    "max_combo": 5,         # 最大连击
    "total_items": 10,      # 总题数
    "correct_count": 8,     # 命中数
    "review_type_desc": "搭档刚刚给一批台词做了情绪标注，帮忙调试角色的演出基调",
    "review_performance_desc": "...",  # 由小游戏子类根据分数生成
}
```

注意：
- **不产出 `creative_prompt`**（氛围型，无实质内容产出）
- `review_type_desc` / `review_performance_desc` 由小游戏自带，MinigameManager 不需要硬编码

## 6. 实现要点

### 6.1 架构

- 继承 `MinigameBase`
- **走 `MinigameContentService` 链路**（LLM 实时生成素材，和 script_fill 类似）
- `_is_generated_minigame_type()` 需新增 `"emotion_tag"`
- 需要在 `MinigameContentService` 中新增 emotion_tag 的 prompt meta、解析逻辑和 fallback

### 6.2 UI 组件

- 台词卡片（居中大字，包含说话人和场景标注）
- 情绪标签按钮组（底部一排，点击后有视觉反馈）
- 进度条 + 连击计数器
- 结算面板

### 6.3 注册

```gdscript
# MinigameManager._register_default_minigames()
register_minigame("emotion_tag", "res://scenes/minigames/emotion_tag.tscn")
```

### 6.4 _is_generated_minigame_type

emotion_tag **是** generated 类型（需要 LLM 实时生成素材），走 `_start_generated_minigame` → `MinigameContentService` 链路。

## 7. 与其他系统的关系

| 系统 | 关系 |
|---|---|
| MinigameManager | 标准注册/启动/结算流程 |
| DevCycleManager | 任务池中的 `emotion_tag` 类型任务触发 |
| GameManager | 结算时 quality 微调（做对多 → 质量+） |
| ChatManager | 林夏 review topic（标准流程，用 `review_type_desc` 驱动） |
| KnowledgeBase | 素材来源（抽取项目中已有的台词） |

## 8. 与 script_fill 的体验对比

| | script_fill | emotion_tag |
|---|---|---|
| 类型 | 产出型 | 氛围型 |
| 玩家行为 | 写/选台词 | 判断情绪 |
| 创作负担 | 中（可点建议降低） | 零 |
| 手感 | 填空 + 提交 | 快速点选 + 连击节奏 |
| 代入感 | "这句台词是我写的" | "我在帮角色调情绪" |
| LLM 依赖 | 重（实时生成场景骨架） | 中（实时生成句子+情绪标签，但格式简单） |
