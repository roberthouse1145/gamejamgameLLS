## 3D 主播演出

表情会持续到下一次切换：

```
expression: strained
```

姿态会持续到下一次切换，并且可以与表情、口型和手势同时播放：

```
posture: thinking
```

身体姿态、手臂姿势和头部姿势是三个独立维度，各自持续、自由组合：

```
posture: lean_forward
arm_pose: arms_crossed
head_pose: head_down
```

手势是一次性动作，结束后回到当前姿态：

```
gesture: wave
```

每条演出命令从自己的能力列表取值：`expression` 对应可用表情，`posture` 对应可用姿态，`arm_pose` 对应可用手臂姿势，`head_pose` 对应可用头部姿势，`gesture` 对应可用手势。开场、情绪变化和明显反应时切换演出状态；同一状态持续时无需重复设置。

## 主播字幕

```
say: 大家晚上好。
```

- 每句使用第一人称自然口语，80 字以内。
- `say` 必须包含主播实际说出或唱出的正文。歌词、哼声、演唱前后的真实口语与弹幕反应都可以直接表现现场。
- 演唱内容优先使用成对音符标记，例如 `say: ♪夜风吹过窗边♪`；音符内仍是主播实际唱出的字词。
- 括号可以在开头补充一次简短的语气、状态或演唱方式，后面必须紧接实际说出或唱出的正文。括号不能独占整条 `say`，也不用于概括唱了几首、稳定度、情绪变化、动作过程或收尾效果。
- 动作和可见反应使用上方演出命令；表现好坏通过现场真实台词与弹幕反应自然成立。
- 字幕会逐字显示，口型会自动播放，并在显示完毕后自动停留、推进。

## 普通弹幕

```
chat: 开播了 | 晚上好
chat 25: 好耶 | 看到了 | 继续继续
```

- 格式为 `chat [数量]: 消息池`，消息之间使用 `|` 分隔。
- 数量表示本条语句发送的弹幕总数；省略数量时，消息池中的内容各发送一次。
- 数量大于消息池条数时，以不放回抽取的方式逐轮使用当前消息池，直到发送满指定数量。
- 每条 `chat` 语句使用独立的临时消息池；当前语句发送完成后，再继续执行下一条直播 DSL。

## 醒目留言

```
sc: 支持本场直播！
sc 4: 好耶 | 支持一下 | 继续加油
```

- 格式为 `sc [数量]: 消息池`，数量表示本条语句发送的醒目留言总数。
- 每条 `sc` 语句同样使用独立的临时消息池，并在发送完成后继续执行后续 DSL。

## 额外停顿

```
wait: 1.5
```

- 格式为 `wait: 秒数`，用于笑场、临场反应或节目段落之间的明显空白。

## 编排要求

- 围绕一件正在发展的直播事件完成开场、变化与结果；开场问候和收尾告别自然融入事件。
- 节目单卡片按顺序影响同一场直播。相邻卡片可以共同作用于一个片段，卡片造成的结果继续影响后面的行动。
- 让姿态、手臂姿势、头部姿势、表情和手势贴合当前台词，而不是每句全部切换。
- 姿态、手臂姿势、头部姿势和表情会持续到下一次切换：情绪回落或明显阶段转换时显式写回 `idle`（表情写回 `default`），整场收尾时全部归位。
- 弹幕要像一个真实直播间：有捧场的、有玩梗的、有提问的、有吐槽的，甚至偶尔有挑事的，语气各不相同。弹幕内容针对主播刚说的话或正在播的内容。
- 主播会接住有趣的弹幕、回答问题或回嘴；至少一次弹幕互动会改变主播接下来做什么，而不只是对上一句作评价。
- 普通互动使用少量弹幕；爆点、翻车或强烈反响使用大数量刷屏。
- 每条语句单独占一行，只使用 `expression`、`posture`、`arm_pose`、`head_pose`、`gesture`、`say`、`chat`、`sc`、`wait`。
