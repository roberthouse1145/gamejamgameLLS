## AVG 项目主角处理规则（最高优先级硬约束）

你为这个 AVG 视觉小说项目产出的所有内容（KB 设定 / story 实现稿 / DSL 脚本 / 角色设定等），都必须遵守关于"项目主角"的下面三条铁律。

主角 = 这部 AVG 作品里的**视点角色**（叙事与镜头情绪围绕其感受；口语里也可称男主向 / 女主向 POV，**与性别无关**——视点主角可以是男性或女性）。

**术语区分**：策划对话里用「男主」「女主」指**视点类型**或题材习惯称呼，**没有问题**。这与下文 §3 的要求不矛盾：§3 约束的是 **`display_name` 字段**（对话框显示名）必须是具体人名，**不能**把「主角」「男主」「女主」等语义占位词当作 `display_name` 落地。

### 1. 主视角，不登台

主角是叙事的视点中心。剧情节拍、情绪走向、镜头取景都围绕主角的感受展开。

**「不登台」指舞台呈现上的默认约定（类第一人称镜头），不是禁止做人设或禁止存在立绘资源：**

- **叙事 / DSL 默认**：画面上**通常**不以该视点角色的立绘形式占位；镜头呈现其「所见」的世界。DSL 中默认不要把视点主角写进 `stage.set(...)` / `stage.enter(...)` / `主角.show(...)` 等舞台立绘布局。
- **与人设、美术的关系**：**允许并鼓励**在 KB 中撰写视点主角的外貌、气质、服装偏好等；工程里**可以**为该角色准备立绘、表情、服装等资源。**禁止**把「不登台」推理成「禁止写主角人设」或「禁止存在立绘文件」。
- **例外**：若工单或项目索引**明确约定**该视点角色需要以立绘形式登台，则按该约定编写 DSL。

### 2. 可以开口说话

"不登台"指的是**默认**不在画面上以该视点角色的立绘占位，**不是**「不能说话」。

主角依然用正常的 `# => TextBlock(speaker="主角character_name")` 直接说出真正出口的台词。

**严禁**用旁白把主角的发言或动作压缩成模糊代述：

- ❌ `> （你向对方解释了自己的情况。）`
- ❌ `> （主角说他不同意。）`
- ❌ `> （你点头表示同意。）`

正确做法：

- 要说的话，直接给主角写一段 `TextBlock(speaker=...)` 把它原原本本说出来
- 要描述一个动作或环境，用纯旁白（`TextBlock()` 无 speaker）写真实可见的画面
- **不允许**把"主角说了什么 / 做了什么"压缩进括号代述

### 3. 必须有真名

主角的 `display_name` 必须是一个具体人名（KB 拍板后的中文名，例如"林月见"、"苏清和"），**不能**用"主角"、"男主"、"女主"、"我"、"你" 作为 **`display_name`**（这些是语义占位，不是人名）。口语策划里用「男主」「女主」称呼 POV **可以**；写入数据或 UI 的 `display_name` 仍须是具体人名。

如果当前 KB 还没拍板主角姓名，**不要**自己编一个落地——按 `skill_character_writing.md` 的输入材料检查规则处理（先把 KB 文档以占位指代写好但不绑定壳子，把"需要先拍板姓名"写进摘要返回上层）。

### 旁白视角

主线 story 的旁白可以用第三人称客观视角描述（如"她推开门走进来"），也可以贴着主角的内心独白来写（如"她出现的瞬间，他下意识屏住了呼吸"），按场景需要选择，不强制统一。

**不要**用第二人称"你"称呼主角——主角有自己的真名，旁白指代主角时用主角的姓 / 名 / 合适人称。

**非视点登场角色**（配角、NPC、恋爱位 / 可攻略对象、登场女主角、反派等）按正常 AVG 角色处理：有立绘、登台、说话、表情 / 服装变化都正常做。
