# Community Feed DSL 语法规范

帖子 DSL 用于 AI 生成论坛线程内容。格式极简，LLM 只负责输出主楼、楼层和楼中楼，不做任何布局说明。

## 核心要求

- 一次输出只允许 **1 条帖子线程**。
- 线程由 **1 条主楼**、若干 **楼层** 和可选的 **楼中楼回复** 组成。
- 每一层楼都可以拥有自己的楼中楼回复。

## 帖子结构

===post===
author: 用户名
time: 发帖时间
likes: 点赞数
replies: 回帖总数
title: 帖子标题

主楼正文（自由文本，可多行）

---reply---
author: 某一层楼的作者
time: 该楼时间
likes: 点赞数

该楼正文

---subreply---
author: 针对这一层楼的回复者
time: 楼中楼时间
likes: 点赞数

楼中楼正文

---reply---
author: 另一层楼的作者
time: 另一层楼时间
likes: 点赞数

另一层楼正文
===end===

## 规则

### 分隔符

| 分隔符 | 作用 |
|--------|------|
| `===post===` | 开始主楼 |
| `---reply---` | 开始一层楼 |
| `---subreply---` | 开始该楼层下的一条楼中楼 |
| `===end===` | 结束当前线程 |

### 头部字段

在分隔符下方，以 `key: value` 格式逐行书写元数据。
到第一个空行为止都是头部区域，空行之后全部是正文。

| 字段 | 必填 | 说明 |
|------|------|------|
| `author` | ✅ | 用户名，要像贴吧/论坛网名 |
| `time` | ✅ | 相对时间，如 `2小时前`、`昨天 14:00` |
| `likes` | ✅ | 点赞/热度 |
| `replies` | ✅ | 楼层总数 |
| `title` | 建议填写 | 主楼标题，尽量像真正论坛贴 |

### 正文要求

- 正文是自由文本，不需要转义。
- 风格必须是贴吧 / NGA / S1 一类论坛口吻，不要写成小红书动态。
- 主楼像一个完整线程的开场，楼层像吧友回帖，楼中楼像针对某层的追答。
- 极少使用 Emoji，可以用少量论坛黑话或口癖。

### 禁止事项

- 不要输出多条主帖
- 不要把每一层楼写成互不相关的新帖子
- 不要输出 JSON
- 不要输出 HTML 或 XML 标签
- 不要输出解释性文字
- 不要在头部区域的 value 中换行
