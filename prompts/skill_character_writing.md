如果当前任务是在项目中正式落实一个新角色，而不只是纯文档修订，那么这项 skill 的交付物包含两部分：

1. 写好或更新 KB 里的角色设定文档
2. 从当前项目里选择一个未占用的预置 AVGCharacter 壳子并占用它

你不能创建新角色资源。你只能在现有模板角色壳子中挑选一个视觉/气质最接近且尚未占用的壳子，然后写入它的 `character_key / character_name / display_name / profile`。

这 4 个字段的职责必须严格区分：

- `character_key`：项目内逻辑 key，例如 `heroine_main`、`rival`
- `character_name`：给 DSL / Writer / 系统引用的稳定角色名。**必须是简短的 ASCII 标识符**，例如 `LinXiaoyue`、`Hero01`、`ProfessorAster`。不要写中文、空格或标点。
- `display_name`：给玩家看到的显示名。这里可以写中文，例如 `林晓月`
- `profile`：外观/气质摘要

不要把 `character_name` 和 `display_name` 都写成中文。Writer 在 DSL 中应该引用 `character_name`，不是 `display_name`。

## 输出格式

使用中文方括号分段，严格按照以下结构：

```
【基本信息】姓名：XX | 年龄：XX | 身份：XX
【性格关键词】3-5 个核心特质词，用顿号分隔
【说话风格】
- 具体语言习惯（必须附带例句或情境说明）
- 例："紧张时句子变短、语速加快"
- 例："习惯用反问句掩饰情感（'你觉得呢？'）"
【核心动机】一到两句话写清驱动力和内心需求
【关系动态】与其他角色的互动模式和情感态度
【行为禁区】角色绝对不会做的事（用 - 列出）
```

## 写作原则

- 每条信息必须能回答"这如何影响角色的对话和行为"
- 性格关键词不超过 5 个，选最有区分度的
- 说话风格至少写 3 条，必须具体到能直接指导生成对话
- 背景故事只保留影响当前行为和动机的部分，删除与场景创作无关的历史细节
- 关系动态着重写互动模式（如"会因认可而开心、因被忽视而赌气"），不写关系史

## 禁止

- 使用 Markdown 格式标记（不要用 #、**、> 等）
- 写"她是一个温柔善良的女孩"这类通用描述
- 堆砌无法指导对话的形容词和背景细节
- 超过 400 字（强制精炼）
- 创建新的 AVGCharacter 资源
- 覆盖已经被占用的角色壳子
- 修改角色壳子的 sprites、emotion_slots、服装或资源路径
- 把 `character_name` 写成中文、带空格的名字，或其他不适合作为 DSL 对象名的文本

## 落地规则

### 落地前的输入材料检查（强制）

在调用 `occupy_character_shell` 之前，必须能从工单描述【输入材料】块（或工单描述里的明确文字）里找出：

- `display_name`：一个**具体的、玩家会在对话框里看到的人名**（中文名为主，例如"林月见"、"苏雨晴"）。**不得是身份占位词**——"主角"、"女主角"、"青梅竹马"、"转校生"、"学姐"这类全部属于占位指代，**不是名字**。
- `character_key`：项目里的稳定 key，例如 `heroine_main` / `protagonist`。如果工单里给了就用工单的，没给就根据角色身份合理生成。
- `profile` 所需的外观/气质材料（发色、瞳色、身高、衣着风格、气质关键词等）。

**如果【输入材料】里没有具体人名，或只给了身份占位词，可以自行拟定一个符合角色性格/背景风格的临时名字。** 正确做法：

- 根据角色设定（性格、身份、题材风格）拟一个合理的临时 `display_name`，在 KB 文档中标注「（暂定名，可随时更改）」
- 正常继续调用 `occupy_character_shell` 落地壳子
- 在最终摘要中**显式写明**：「display_name 为自行拟定的暂定名：XX，Controller 可在后续工单中更新」

### 通过检查后的壳子选择

- 完成 KB 文档后，如果这是一个"让角色进入项目"的任务，且【输入材料】检查已通过，必须继续调用 `list_character_shells` 查看可用壳子
- 只能从 `occupied=false` 的预置壳子中选择
- **选壳子必须独立决策**：无论上层 controller 或 task 描述中是否建议了具体的壳子 ID，你都必须自行阅读 `list_character_shells` 返回的每个可用壳子的 `profile` 字段，逐一与角色设定的视觉气质进行比对，然后独立得出选择。不得直接沿用外部建议的 ID 而跳过比对。
- 选择依据优先级：① 发型/发色 ② 性格气质/服装风格 ③ 体型/年龄感 ④ 编号（最低优先级，仅在前三项均无明显差异时参考）
- 如果所有可用壳子都与角色气质差异较大，必须在摘要中说明"最接近的选择是 char_xxx，原因是……，但存在以下不匹配：……"
- 绑定时必须调用 `occupy_character_shell`
- 调用 `occupy_character_shell` 时，`character_name` 必须使用 ASCII 标识符，`display_name` 再写中文名
- 如果没有合适壳子，不得硬绑到不合适或已占用的壳子；应在最终摘要中明确说明"KB 已完成，但项目角色壳子不足/不匹配"
- 摘要中必须写清楚：更新了哪篇角色文档、最终占用了哪个 `char_xxx` 壳子、**选择该壳子的具体理由**（引用 profile 原文中的哪些词与角色设定匹配）；如果没占用成功，也要明确写出原因
