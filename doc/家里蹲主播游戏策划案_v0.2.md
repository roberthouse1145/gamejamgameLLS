## 1. 游戏概述

### 1.1 一句话简介

玩家操作一个**桌面 OS 界面**，扮演被白富美青梅欺骗、签下 MCN 合约的**家里蹲宅女**，靠直播打工还债——否则将背上巨额违约金，从此沦为青梅的宠物。

### 1.2 核心体验

- 玩家操纵的是**女主角**，但她的性格底色很重，玩家的选择会被她的性格过滤——降低玩家的表演压力
- 女主是**家里蹲**：看番、打游戏、买谷子，这些宅生活本身就是直播素材（消费即生产）
- 喜剧外壳、压力内核（基调待最终确认）

### 1.3 设计支柱（五条分界线）

1. **非 Chat Game**：克制自由输入。大部分情况下玩家不做自由输入，而是通过**间接输入（日程安排、素材与方案选择）+ 游戏数值**驱动 LLM 演绎
2. **决策前置、演出放映**：直播中零决策、零打字；决策全部发生在**准备阶段**与**结算后**
3. **数值是真相，LLM 是表达**：核心结果由代码预结算，LLM 只负责把结果演出来
4. **消费即生产**：宅生活 → 素材 → 直播内容 → 收益 → 更好的宅生活
5. **粉丝是向量，朋友是角色**：粉丝只是数值与氛围，朋友才是故事（唯一具名例外：榜一 = 鹿铃，见 8.5）

## 2. 核心循环

```
宅生活（看番/打游戏/买谷子）
      ↓ 产出
     素材（内容含量）
      ↓
选择素材与本场直播构思
      ↓ 预结算 + LLM 演出
   直播放映（3~5 分钟游戏时间）
      ↓
   结算（在线/涨粉/打赏/粉丝构成）
      ↓
下播处理（舆情菜单、朋友消息、下播日记）
      ↓
 金钱 → 还债/升级设备/买更多素材
 压力/宅欲/孤独 → 软约束下一天的安排
```

## 3. 时间结构与流程

### 3.1 90 天 / 6 期判定

- 总时长 **90 天**，每 **15 天**一次契约判定，共 **6 期**
- **判定失败** → 提前进入一般结局判定（最后 2~3 天为"结局周"）
- **撑到 90 天** → 进入好结局判定
- 好结局、一般结局均为**多结局**

### 3.2 每日 3 时段

- 每日 **上午 / 下午 / 晚上** 3 个时段，每时段一次行动
- 行动类型：打工 / 宅生活 / 陪朋友 / 直播 / 休息——全部是**事件**（事件即行动；技能 EXP 从事件与直播实战中获得，见 5.8；**不存在"练习"动作**）
- 直播频次由玩家自选，不做硬性排班——约束来自数值而非规则（见 3.3）

### 3.3 软约束原则

- **直播频次由玩家自选**，不做硬性排班
- 约束来自数值而非规则：**三属性（压力/宅欲/孤独）+ 素材库存（一次性，见 6.1）**
- **压力过满 → 坏结局线；宅欲过满 → 摆烂；孤独过满 → 关系状态恶化**

## 4. 数值系统

### 4.1 分类总则：属性 / 资源 / 成长 / 关系

| 类别 | 内容 | 说明 |
|---|---|---|
| **属性**（女主状态，0~100，波动、阈值、喂 LLM） | 压力、宅欲、孤独 | 见 4.2 |
| **资源**（非属性） | 金钱（货币）、时间（3 时段）、素材库存（一次性素材，见 6.1）、热度/收益/粉丝构成/炎上（跨场） | 金钱就是金钱，不是属性 |
| **成长**（非属性） | 五维技能、**当前人设**的熟练度/固化度（转生后冻结归档，见 4.10）、主播等级（演出预算 + 修饰槽 + 解锁）、知识面 | 长期积累 |
| **关系**（非属性） | 各朋友的好感、信任、依赖 | 各自独立 |

### 4.2 三属性（常驻可见条 ×3，黄油式驱力）

| 属性 | 涨的来源 | 消解方式 | 高了会怎样 |
|---|---|---|---|
| **压力** | 直播、打工、炎上、债务、判定临近 | 宅生活、陪朋友、休息 | >60% 演出降质 / >80% 摆烂 / **100% = 坏结局** |
| **宅欲** | 被迫做"正事/表演"（打工、直播、陪人） | 宅生活（看番/游戏/买谷） | >70% 心不在焉、演出打折 / >90% 摆烂（"下周再努力吧"） |
| **孤独** | 宅生活（隔绝）、**直播（单向关注不填坑）** | 陪朋友 | >70% 下播日记变丧 / >90% 关系事件更容易恶化 |

**关键洞察（情感内核）**：直播**同时涨宅欲和孤独**——她被迫当众表演，但观众是单向关注，没有人真的认识她。合约逼她做的是唯一"喂不饱她、反而饿死她"的工作。

### 4.3 阈值与释放事件（黄油式手感）

- **满值释放事件**：
  - 宅欲满 → 深夜爆肝游戏事件（时间损失 + 素材爆率）
  - 孤独满 → 半夜给青梅发消息（关系事件，露出破绽）
- **交叉作用**：
  - 压力高时，宅生活回宅欲更快（报复性消费）
  - 宅欲高时，直播扣压力更多（被迫营业更痛）

### 4.4 防刷法检验（属性的存在意义）

| 刷法 | 后果 |
|---|---|
| 只直播 | 三属性全涨 → 演出降质、关系恶化、摆烂 |
| 只打工 | 宅欲↑↑ → 摆烂；且合约进度停滞 → 判定失败 |
| 只宅生活 | 孤独↑↑ → 关系状态恶化；且没钱 → 判定失败 |
| 只陪朋友 | 判定失败（自然结果） |

素材库存与合约判定是天然刹车——不需要精力类假刹车。

### 4.5 被否决的数值及理由

| 数值 | 否决理由 |
|---|---|
| 精力 | 3 时段已封顶每日行动次数，精力是第二根行动条，冗余 |
| 快乐值 | 宅生活本身已被机制奖励（素材 + 灵感 buff），再立一条即重复 |
| 激情值/动力 | 用"压力高时休息效果打折、下播日记语气变丧"表达，不做第二条压力条 |
| 健康条 | 用压力慢性效果表达，上限管理代替第二根条 |

（孤独曾被否决，后因承担"防刷法 + 朋友系统驱动"的双重职责而被采纳为属性。）

> **"精力"被否决 ≠ "演出预算"被否决**：被否决的精力是**每日行动条**（与 3 时段重复，见上表）；演出预算是**单场牌组强度上限**（构筑约束，见 5.9），作用域完全不同——前者管"一天能做几件事"，后者管"一场能编多重的节目"。

### 4.6 五维技能（成长数值核心）

**五个互不包含的维度，对应五个身体部位/能力层：手 / 嘴 / 声 / 演 / 技。**

| 维度 | 一眼即懂 | 边界（不含什么） | 底层 |
|---|---|---|---|
| 🎮 **游戏力** | 玩游戏的水平（操作、通关、理解） | 不含说话、不含搞笑 | 手 |
| 🗣️ **杂谈力** | 会聊天、会接梗、能救场；**含接弹幕、回 SC、怼黑粉** | 不含游戏操作、不含扮演 | 嘴 |
| 🎤 **歌唱力** | 唱歌、音准、声线质感（歌回 / ASMR / 电台） | 不含演技 | 声 |
| 🎭 **演出力** | 演人设、夹嗓子、卖萌、营业——"皮套后面的表演" | 不含真本事、不含技术 | 演 |
| 💻 **杂项力** | 设备、OBS、调音、剪辑切片等台后技术 | 不含任何台前能力 | 技 |

**设计决定：**

- 曾设第六维"反应力"（接弹幕/应对黑粉），因与杂谈力同为"靠嘴输出"、在数值上作用于同一位置而**并入杂谈力**——两个技能解释同一场直播就是冗余
- **技能既影响代码结算，也作为能力边界注入直播生成**。同一素材、同一构思在低等级和高等级下，会体现为不同的判断完整度、执行稳定度和纠错速度；成长属于中之人，不跟人设皮套绑定
- 技能升级获得公共成长点，用于技能树内自由加点；成长节点只强化中之人能力，不授予卡牌
- 成长来源：**事件 + 实战**——事件（打工/宅生活/陪朋友/剧情）按类型给对应系 EXP；直播实战由本场消耗的素材提供特定领域 EXP。**不存在"练习"动作**
- **知识面**（深度/广度，素材利用率放大器）保留为独立成长值，不占五维（是否并入杂项力：待定）

### 4.7 其他长期数值

- **人设数值**（每个档位一套）：熟练度、固化度
  - 长期扮演同一档位 → 熟练度↑（演出基础倍率↑），但同时固化度↑（新粉转化率↓）
  - 人设档位 ≠ 人设数值：档位是"选择演什么"，数值是"演得多熟/观众多固化"
- **关系**：与每个朋友的好感、信任、依赖（各自独立）

### 4.8 跨场数值（不上常驻条）

- **粉丝构成向量**（见 4.9）
- **炎上值**：跨场累计，压力源放大器
- **契约进度**：债务余额、6 期判定完成情况

### 4.9 粉丝构成向量（五类互斥）

**结构**：`路人 R / 男粉 M / 女粉 W / 核心粉 C / 黑粉 B`，归一化百分比：R+M+W+C+B = 100%。路人无性别；核心粉、黑粉从男女粉转化而来。

**每场直播后的变动流程：**

1. **基础扰动 Δ** = 构思类型 fanBias + 素材 affinity 修正
2. **新增路人** = 峰值在线 × 转化率；转化率 = base × (1 − 0.8 × (C+B))
   - **核心粉与黑粉占比越高，新粉越难流入 —— "观众固化"的数值落地**
3. **路人 → 男女粉**：按质量轴留存系数（见 7.3）
4. **男女粉 → 核心粉**：打赏/舰长事件概率转化（核心粉 = 金主）
5. **黑粉**：增 = 炎上量 × 黑化系数；每场自然衰减 10%（淡出，但节奏事件可复活）
6. **归一化**

**反哺（让向量真正影响决策）：**

- **变现**：打赏权重 = (0.3R + 0.6(M+W) + 1.6C − 0.5B)——核心粉是金主，"转化核心粉"是经营目标
- **破圈**：新粉转化率 ∝ R 占比。长期演同一人设 → 结构偏科 → 破圈停滞
- **舆论**：B > 15% → 负面反馈更强，并进入状态快照（LLM 演"黑粉蠢动的弹幕氛围"）
- **人设切换 = 毕业转生**（唯一途径，见 4.10）：中之人同时只能扮演一个 Vtuber，开播前不可换皮套。切换是资产级事件，不再是轻量惩罚
  - 这收紧了核心张力：**专精 → 熟练度↑、变现↑，但固化 → 增长停滞；破局只能转生 → 资产清零、从新皮套重来**
- **演出语境**：构成向量作为状态快照的一部分给 LLM，LLM 只演"氛围"，不演有名有姓的粉丝个体——**唯一例外：榜一鹿铃**（见 8.5，具名角色，单独人物卡）

**显示简化**：一根五段条形图 + 总粉丝数 + 一句提示（如"黑粉扎堆"/"观众结构固化"），玩家看趋势，不读数字。

### 4.10 毕业转生（人设切换的唯一途径）

**为什么存在**：现实中一个中之人同时只能扮演一个 Vtuber。开播前随便选皮套是玩法妥协，破坏代入感——人设卡不能直接切换。换皮套 = 旧 Vtuber 毕业、中之人带经验转生为新皮套，是**资产级事件**，不是轻量惩罚。

**规则：**

- **触发**：玩家主动发起（入口待定：直播姬应用内 / 管理中心），无冷却，但门槛阻止滥用（见下）
- **门槛（待测试）**：当前人设累计直播场次 / 粉丝规模 / 主播等级达到条件才可发起转生
- **效果**：
  - 当前人设的熟练度、固化度**冻结归档**（不再变化，不可再扮演）
  - 旧人设卡从图鉴"扮演中"变为"已毕业"
  - 切换为新人设档位（**新人设 = 转生的解锁目标**，转生即新档位的获取方式，解决"新档位从哪来"）
  - 与皮套无关的资源全部保留：技能、知识面、素材库存、金钱、关系、契约进度
- **粉丝构成向量重建（转生红利，防"纯清空=永不转生"）**——转生前 `R/M/W/C/B`，转生后初始盘按残留规则生成（比例待测试）：
  - **路人 R ×0.5 继承**：新皮套自带路人盘（圈内消息传播）
  - **一般粉 M/W ×0.2 跟随**：一部分老粉陪皮套走
  - **核心粉 C：×0.1 认出来（→新皮套 C）；×0.3 回踩（→B）；×0.6 流失**：金主被毕业伤得最深——"你越成功，转生越痛"
  - **黑粉 B ×0.5 跟随**：黑粉记仇，跟着新皮套继续黑——**转生换不掉你的黑粉，只会丢掉你的金主**
  - 归一化后粉丝总数大幅缩水；熟练度、固化度重置为新人设初始值（增长压制解除）
- **与固化度联动**：固化度压制新粉转化 → 长期演同一人设增长停滞；转生解除压制但资产清零。决策 = "存量变现 vs 清零重来"
- **数值叙事**：与 Build 6（地雷系，4.9 / 5.14）形成全游戏最狠闭环——地雷系核心粉转化全游戏最高、黑粉共生，**转生时金主丢得最干净、黑粉跟着走**：你越成功，越走不出去

## 5. 临时直播构思系统

### 5.1 为什么不继续做永久节目卡构筑

本作是叙事向、轻模拟经营养成，并非以直播构筑为全部流程的纯经营游戏。永久行为卡池、接口拼图、演出预算、素材锁卡和卡牌过滤需要玩家长期记忆一套独立规则，但只在日常循环的一小段出现，会放大心智压力并割裂约会、外出、打工等养成节奏。

直播仍需要玩家输入，也仍需要结构化差异，否则“自由输入”会把创作压力转嫁给玩家，“LLM 自行编排”又容易重复。因此当前采用更轻的中间层：**每次开播只为所选素材生成 2～3 个临时直播构思，玩家选一个，不收集、不组卡、不升级构思。**

### 5.2 生成时机与数据归属

- 日常生活触发素材时，只写入这份素材的稳定事实：发生了什么、有哪些公开/私密信息、可用于直播的内容细节和可能活动。**不在素材生成时预写直播构思。**
- 最终目标是在玩家选择素材后，再根据**素材实例 + 当前人设 + 中之人五维技能 + 三属性状态 + 粉丝状态 + 关系状态 + 该人设近期直播摘要**临时生成构思。这样素材本身不会被某次开播时的状态永久污染。
- 当前版本不接入构思生成 Prompt。选择素材后由代码按素材活动给出 2～3 个内置构思，先验证选择、结算、快照和直播播放链路；待策划完成 Prompt 二改后再替换这一来源。
- 构思只存在于本次开播草稿和最终直播快照中。离开准备流程可以暂存恢复；素材消耗后不进入玩家收藏。

### 5.3 构思最小字段

| 字段 | 所属 | 用途 |
|---|---|---|
| `approachId` | 技术字段 | 本批临时候选内唯一标识 |
| `approachType` | 代码字段 | 从固定类型表选择，决定经营侧倾向；LLM 不填写数值 |
| `displayName` | 玩家可见 | 简短构思名 |
| `displayDescription` | 玩家可见 | 一句话说明今晚准备怎么播 |
| `directorPrompt` | LLM 导演字段 | 只注入后续直播编剧，描述核心看点、推进方式和收束条件 |

玩家可见说明与导演指令必须分离。玩家不需要看 Prompt 工程内容，直播编剧也不能把玩家 UI 文案当成足够精确的导演约束。

### 5.4 固定构思类型与经营意义

`approachType` 只能从代码固定表选择：`analysis`（深入拆解）、`challenge`（目标挑战）、`audience_interaction`（弹幕共创）、`performance`（舞台表现）、`personal_story`（个人切入）、`production`（企划制作）。

- 类型只提供稳定的三轴、压力、粉丝倾向和相关技能权重；具体文案和现场事件由本次构思决定。
- LLM 无权新增类型、填写三轴或决定收益，避免自然语言漂移破坏经营平衡。
- 素材决定实际获得的领域熟练度 EXP；构思类型只改变本场经营侧重，不取代“做什么就练什么”的成长规则。

### 5.5 当前实现边界

- 当前代码只按素材活动选择 2～3 个类型不同的内置构思，不发起 LLM 请求，也没有构思生成缓存或 repair。
- 内置构思与未来临时生成构思共用同一最小数据结构、选择 UI、计划快照和结算链路，因此后续只替换候选来源，不恢复旧卡牌系统。
- 未来接入前必须由策划完成 Prompt 与 Lab 样本；没有通过实机对比前，不把“结合成长、状态和历史动态生成”写成已完成功能。

### 5.6 AI 呈现原则

AI 是内容生产基础设施，不是游戏内需要反复宣传的角色。玩家体验到的是“她从今天的经历里想到几种播法”和不同成长状态带来的内容差异，而不是“正在调用 AI”“自由生成无限可能”。除非题材明确需要，玩家界面不主动暴露 LLM 工作过程。

- **等待要属于当前情境**：浏览器显示页面加载，外出显示行程衔接，直播显示主播整理思路；不另开模型调用、内容生成或 Prompt 处理对话框。
- **失败要说明玩家后果和恢复动作**：技术错误只写入日志，界面只回答什么没有完成、资源是否消耗、玩家如何继续。玩家文案不直接展示供应商、模型、Prompt、请求或解析错误。
- **变化靠内容证明**：宣传和界面只描述素材、构思、技能、状态与历史会影响本次内容，不承诺“完全自由”“无限可能”之类不可验证的能力。

## 6. 素材系统

### 6.1 核心答案：一次性

素材**播一场烧一张**，库存里没有"剩余含量"：

- 每场直播消耗一份素材，用后即焚；再次使用需重新获得（重新进货 = 新实例）
- **为什么不是"有含量"（depth）**：预结算 + LLM 演绎架构下，同一素材重复播容易产出高度相似的内容；重复 = 内容贬值，含量机制给不了稳定差异
- 一次性让**每场都是新题面**：素材供给量直接决定可播场次，素材成为真正的消耗品；内容差异来自素材、构思和角色状态，而不是同一素材的深浅
- 素材消耗节奏变快 → 获取管道（6.3）供给频率需相应上调（待测试）

### 6.2 两种类型

| 类型 | 例子 | 经济角色 |
|---|---|---|
| 消耗型 | Sbeam 游戏、追新番、谷子开箱、论坛热梗 | 播一场即焚；对应游戏实况/歌回/杂谈/整活 |
| **商单型** | 游戏推广、恰饭广告（type: sponsor） | **保底金钱 + 锁定广告卡 + 满意度判定**（见 6.5）——钱和节目质量二选一的高压线 |

素材实例无消耗曲线：只有 `definition_id / instance_id`，没有含量/进度/新鲜度——用即删，不存在"陈旧素材"。

### 6.3 获取管道（稳定供给）

- **购买流（确定性）**：Sbeam 商店、周边店——钱的出口，防金钱溢出
- **白嫖/事件流（半随机）**：限免、朋友安利、论坛热梗、外出事件——时间的出口
- **轮换池**：商店固定上架 + 季节性活动轮换，保证后期供给
- **技能挂接**：知识面提高素材利用率——技能是素材的放大器
- 一次性化后供给频率上调：**每场直播消耗一份**，库存余量应能支撑玩家“直播为主的运营路线”（数值待测）

### 6.4 素材是日常经历的稳定记录

素材保存日常活动中已经成立的事实和可公开内容，是直播构思的输入，不是预写节目单。素材可继续使用卡片视觉呈现，但数据上不再与行为卡共享接口、槽位、锁卡或组合字段。

一份素材的核心字段收敛为：名称与玩家说明、内容事实/导演资料、可进行活动、基础热度、三轴基础修正、五领域 EXP、领域适配、素材类型与可选商单条款。素材实例还可保存本次日常活动动态生成的摘要、事实与隐私边界。

**素材的三轴修正与领域适配**（接入 7.3 结算）：

- 素材自带轴修正与五领域 affinity；构思类型提供本场经营倾向，技能等级放大相关领域表现
- 素材还直接提供五领域 EXP，保证做什么就练什么

**待拍板**：素材 prompt 来源：核心素材手写保质感，其余 LLM 生成初稿 + 人工审核（是否接受混排）。

### 6.5 素材完整字段与 tag 系统

```json
{
  "id": "game_trash_hunter",
  "type": "consumable",      // consumable（消耗型）/ sponsor（商单型）
  "title": "《粪作猎人》",      // 素材名；仅作开播前的标题占位
  "description": "玩家可见描述。",
  "activities": ["play", "challenge", "react", "discuss"],
  "affinity": { "talk": 1.5, "game": 1.0, "act": 0.8 },  // 对系别的天然适配
  "axes": { "hook": 1, "quality": -1 },                    // 素材自带三轴修正
  "skillExp": { "game": 30, "talk": 30 },
  "prompt": "<string>"
}
```

- `activities` 用于约束代码内置构思方向；未来也可作为构思生成的结构化输入
- **直播标题 = 开播时 LLM 中途生成**（见 10.2）：素材名只作开播前占位，中途生成可使用当前人设、素材、已选构思和主播状态
- 商单条款单独保存在 `sponsor` 字段，只描述保底收益和质量阈值，不再携带节目槽或锁定内容

### 6.6 活动词表

| 类 | tag |
|---|---|
| 内容领域 | `game`, `trash_game`, `masterpiece`, `casual`, `horror`, `story_rich`, `music`, `voice_acting`, `moe`, `otaku_culture` |
| 玩法特征 | `boss_fight`, `high_difficulty`, `hardcore`, `speedrun`, `multiplayer`, `rage_bait` |
| 话题特征 | `gossip`, `life_story`, `hot_topic`, `confession`, `rant` |

活动词表按需扩展；原则是描述素材现场真实可做的事，并用于构思生成和降级，不把题材名词都膨胀成玩法标签。

## 7. 直播系统

### 7.1 三拍制（待测试）

演出结构：**开头 / 中间 / 结尾**。最终形态（每拍内容、长度、快进交互）需长期测试后定稿，当前不深入。

### 7.2 预结算架构（关键）

- **开播瞬间，代码先算出完整场结果**：三轴、产出、粉丝变动全部由代码预结算
- **LLM 只是照既定结果演绎**——它不知道结果，只负责演出
- 演出**不反写核心数值**（纯装饰）；LLM 输出标签仅写回体验记忆与叙事层（下播日记、弹幕氛围）

由此得到的性质：

- **跳过/快进永远安全**：结算已存在，跳过演出 = 丢弃装饰、立刻结算，同时省 token
- **断网/失败有兜底**：数值不依赖 LLM

### 7.3 三轴结算管线

```text
① 基础盘   = 素材基础热度 × 粉丝基数
② 三轴累计 = 固定构思类型注入 × 相关技能与素材适配系数 + 素材轴修正
③ 产出换算（单轴对单产出的纯粹映射，可读性优先）：
   峰值在线 = 基础盘 × f(噱头)
   涨粉     = 峰值在线 × g(质量) × 路人转化率(受固化度压制，见 4.9)
   打赏     = 峰值在线 × h(效果) × 核心粉权重(0.3R + 0.6(M+W) + 1.6C − 0.5B)
④ 粉丝构成偏移 = 构思类型 fanBias → 归一化
```

- 是否让打赏小额吃质量（如 `打赏 = 效果为主 + 质量×0.2`）：待测试；当前基准为纯粹映射
- 三属性接入：压力高 → 全轴小幅降质；宅欲高 → 演出打折；孤独高 → 影响关系事件与下播日记

**结算面板（下播后玩家所见）：**

```text
┌───────────── 📊 直播结算 ─────────────┐
│  峰值在线   2,847 人      (噱头 ↑↑)   │
│  新增粉丝   +312          (质量 ↑)    │
│  打赏收益   ¥1,840        (效果 ↑↑)   │
│  粉丝构成   R32 M41 W15 C9 B3         │
│  合约进度   ¥18,400 / ¥50,000         │
└───────────────────────────────────────┘
```

### 7.4 流水线生成（表现层优化）

逐拍生成：玩家观看第 N 拍 AVG 演出时，后台生成第 N+1 拍——感知延迟被阅读时间吞掉。属于表现层优化，后期实现。

### 7.5 事前安排 / 事后处理

- **连麦朋友** = 准备阶段的一个行动（"今晚邀请网友连麦"），朋友状态/好感影响演出效果——朋友系统接入直播的唯一通道
- **黑粉/炎上无法在直播中救场** → 下播后的**舆情事件**：2~3 个菜单选项（发动态回应 / 冷处理 / 装死 / 道歉），影响粉丝构成与压力

## 10. 桌面 OS 界面

### 10.1 UI 总原则

1. **向导式，每步一件事**：多步骤流程用"步骤侧边栏 + 下一步"推进，玩家永远只面对一个问题；未完成时下一步置灰（门控），不会漏步骤
2. **界面各守其位**：女主三属性**不显示在直播软件内**——直播软件没有资格对她评头论足。三属性常驻于 OS 任务栏托盘（三个迷你条，随时可见）+ 日程界面大面板；直播软件后台读取数值用于结算与快照，但不显示
3. **不评头论足**：所有界面只提供信息（数值、接口族），不提供建议、警告、评分——判断是玩家的功课
4. **自然隐藏 AI**：后台内容生产不弹技术对话框；等待、成功和失败都由当前应用自己的状态表达，并提供符合情境的恢复动作

### 10.2 开播向导（V-Stream Studio，三步）

当前流程：

1. **选择素材**：从日常生活获得的素材库存中选一份。素材只展示“今晚有什么可播”和领域 EXP，不展示旧卡槽、锁卡或节目预算。
2. **选择直播构思**：素材选中后立即显示 2～3 个内置构思，用并列方案块展示 `displayName`、`displayDescription` 与固定类型的简短经营倾向。玩家只需选一个。LLM 候选来源待 Prompt 二改后再接入。
3. **确认开播**：确认当前人设、素材、所选构思、预结算和“占用 1 时段”。正式直播标题在入场阶段根据素材与构思生成，随后构思的 `directorPrompt` 进入直播 DSL 生成。

构思选项是卡片式视觉组件，但不是可收集卡牌，不进入卡库，也没有稀有度、升级、槽位或组合规则。

### 10.3 OS 应用清单

- **直播软件（V-Stream Studio）**：开播向导 + 演出界面（弹幕流、SC 特效、立绘表情差分、声音指示条——前端氛围是主力，LLM 文本可以短）
- **聊天软件**：青梅、朋友、粉丝群
- **论坛**：刷帖回帖，素材与热梗来源
- **购物**：Sbeam、周边店（素材购买流）
- **浏览器**：扩展内容位
- **任务栏托盘**：三属性迷你条常驻（压力/宅欲/孤独）
- 手写内容撑质感（论坛帖子、聊天记录），LLM 撑变化

## 11. LLM 架构原则

1. **数值是真相，LLM 是表达**：核心结果代码预结算；LLM 输出标签仅写回体验记忆与叙事层
2. **构思先行，标题与内容跟随**：玩家选定构思后，入场动画期间用短请求生成直播标题（人设 + 素材 + 构思 + 主播状态 → 一行 ≤48 字），再把同一构思的导演指令注入 DSL 生成。标题失败时回退素材名，DSL 照常生成；构思本身当前来自代码内置选项
3. **状态快照**：生成前给 LLM 一份快照 = **当前人设档位** + 相关技能等级 Prompt + **三属性当前值** + 本场素材事实 + **所选直播构思的导演指令** + 关系上下文 + 粉丝构成（观众氛围）+ 筛选后的该人设近期直播摘要
4. **三层记忆**：
   - 事实账本（代码存）：钱、合约进度、粉丝数、大事——LLM 无权改
   - 关系记忆（代码存）：谁是谁——朋友、榜一鹿铃（具名）、房管（半边界）
   - 体验记忆（LLM 摘要）：每场直播后压成摘要，下播日记/对话时注入
5. **成本控制**：按节拍短生成（1~2 秒/拍）；开场白缓存；弹幕 = 模板池 + LLM 点缀混合；跳过演出省 token；标题生成是极短请求，失败零成本回退

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| 一致性（LLM 遗忘/篡改事实） | 事实账本 + 预结算 + 关系记忆代码化 |
| 成本 | 短节拍生成、跳过省 token、弹幕模板混合 |
| 重复性 | 素材轮换（一次性库存）+ 事件库 + 状态变量注入 |
| 表现力不足 | 前端氛围（弹幕流/SC/立绘差分）承担质感，文本短 |
| 决策负担 | 常驻条仅 3 根；粉丝向量只显示趋势；每场只比较 2～3 个临时构思；向导每步一件事 |
| 直播内容重复 | 当前先用素材与固定类型构思控制差异；结合成长、状态、关系与近期记录的临时生成待 Prompt 与 Lab 验证后接入 |
| AI 抢戏 | 不弹模型对话框、不在玩家 UI 吹嘘自由生成；以角色自然整理思路和内容变化体现能力 |
