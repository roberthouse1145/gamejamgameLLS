- 参赛目标：腾讯 2026 游戏创作大赛 AI 赛道

## 1. 游戏概述

### 1.1 一句话简介

玩家操作一个**桌面 OS 界面**，扮演被白富美青梅欺骗、签下 MCN 合约的**家里蹲宅女**，靠直播打工还债——否则将背上巨额违约金，从此沦为青梅的宠物。

### 1.2 核心体验

- 玩家操纵的是**女主角**，但她的性格底色很重，玩家的选择会被她的性格过滤——降低玩家的表演压力
- 女主是**家里蹲**：看番、打游戏、买谷子，这些宅生活本身就是直播素材（消费即生产）
- 喜剧外壳、压力内核（基调待最终确认）

### 1.3 设计支柱（五条分界线）

1. **非 Chat Game**：克制自由输入。大部分情况下玩家不做自由输入，而是通过**间接输入（日程安排、组卡、菜单选择）+ 游戏数值**驱动 LLM 演绎
2. **决策前置、演出放映**：直播中零决策、零打字；决策全部发生在**准备阶段**与**结算后**
3. **数值是真相，LLM 是表达**：核心结果由代码预结算，LLM 只负责把结果演出来
4. **消费即生产**：宅生活 → 素材 → 直播内容 → 收益 → 更好的宅生活
5. **粉丝是向量，朋友是角色**：粉丝只是数值与氛围，朋友才是故事（唯一具名例外：榜一 = 鹿铃，见 8.5）

## 2. 核心循环

```
宅生活（看番/打游戏/买谷子）
      ↓ 产出
     素材（内容含量）
      ↓
组卡开播（人设卡 + 行为卡）
      ↓ 预结算 + LLM 演出
   直播放映（3~5 分钟游戏时间）
      ↓
   结算（收益/粉丝构成/炎上）
      ↓
下播处理（舆情菜单、朋友消息、下播日记）
      ↓
 金钱 → 还债/升级设备/买更多素材
 压力/宅欲/孤独 → 软约束下一天的安排
```

## 3. 时间结构与流程

### 3.1 90 天 / 6 期判定

- 总时长 **90 天**，每 **15 天**一次契约判定，共 **6 期**
- **判定失败** → 提前进入一般结局判定（最后 2~3 天为"结局周"）
- **撑到 90 天** → 进入好结局判定
- 好结局、一般结局均为**多结局**

### 3.2 每日 3 时段

- 每日 **上午 / 下午 / 晚上** 3 个时段，每时段一次行动
- 行动类型：打工（金钱+EXP）/ 宅生活（素材）/ 练习（技能 EXP）/ 陪朋友（关系+减压力+减孤独）/ 直播 / 休息（减压力）
- 直播频次由玩家自选，不做硬性排班——约束来自数值而非规则（见 3.3）

### 3.3 软约束原则

- **直播频次由玩家自选**，不做硬性排班
- 约束来自数值而非规则：**三属性（压力/宅欲/孤独）+ 素材含量**
- **压力过满 → 坏结局线；宅欲过满 → 摆烂；孤独过满 → 社交事故**

## 4. 数值系统

### 4.1 分类总则：属性 / 资源 / 成长 / 关系

| 类别 | 内容 | 说明 |
|---|---|---|
| **属性**（女主状态，0~100，波动、阈值、喂 LLM） | 压力、宅欲、孤独 | 见 4.2 |
| **资源**（非属性） | 金钱（货币）、时间（3 时段）、素材含量、热度/收益/粉丝构成/炎上（跨场） | 金钱就是金钱，不是属性 |
| **成长**（非属性） | 技能等级、人设熟练度/固化度、主播等级/卡槽 | 长期积累 |
| **关系**（非属性） | 各朋友的好感、信任、依赖 | 各自独立 |

### 4.2 三属性（常驻可见条 ×3，黄油式驱力）

| 属性 | 涨的来源 | 消解方式 | 高了会怎样 |
|---|---|---|---|
| **压力** | 直播、打工、炎上、债务、判定临近 | 宅生活、陪朋友、休息 | >60% 演出降质 / >80% 摆烂 / **100% = 坏结局** |
| **宅欲** | 被迫做"正事/表演"（打工、直播、陪人） | 宅生活（看番/游戏/买谷） | >70% 心不在焉、演出打折 / >90% 摆烂（"下周再努力吧"） |
| **孤独** | 宅生活（隔绝）、**直播（单向关注不填坑）** | 陪朋友 | >70% 下播日记变丧 / >90% 社交事故（直播中绷不住人设） |

**关键洞察（情感内核）**：直播**同时涨宅欲和孤独**——她被迫当众表演，但观众是单向关注，没有人真的认识她。合约逼她做的是唯一"喂不饱她、反而饿死她"的工作。

### 4.3 阈值与释放事件（黄油式手感）

- **满值释放事件**：
  - 宅欲满 → 深夜爆肝游戏事件（时间损失 + 素材爆率）
  - 孤独满 → 半夜给青梅发消息（关系事件，露出破绽）
- **交叉作用**：
  - 压力高时，宅生活回宅欲更快（报复性消费）
  - 宅欲高时，直播扣压力更多（被迫营业更痛）

### 4.4 防刷法检验（属性的存在意义）

| 刷法 | 后果 |
|---|---|
| 只直播 | 三属性全涨 → 演出崩、事故、摆烂 |
| 只打工 | 宅欲↑↑ → 摆烂；且合约进度停滞 → 判定失败 |
| 只宅生活 | 孤独↑↑ → 社交事故；且没钱 → 判定失败 |
| 只陪朋友 | 判定失败（自然结果） |

素材含量与合约判定是天然刹车——不需要精力类假刹车。

### 4.5 被否决的数值及理由

| 数值 | 否决理由 |
|---|---|
| 精力 | 3 时段已封顶每日行动次数，精力是第二根行动条，冗余 |
| 快乐值 | 宅生活本身已被机制奖励（素材 + 灵感 buff），再立一条即重复 |
| 激情值/动力 | 用"压力高时休息效果打折、下播日记语气变丧"表达，不做第二条压力条 |
| 健康条 | 用压力慢性效果表达，上限管理代替第二根条 |

（孤独曾被否决，后因承担"防刷法 + 朋友系统驱动"的双重职责而被采纳为属性。）

### 4.6 长期数值（角色质地）

- **人设数值**（每个档位一套）：熟练度、固化度
  - 长期扮演同一档位 → 熟练度↑（演出基础倍率↑），但同时固化度↑（新粉转化率↓）
  - 人设档位 ≠ 人设数值：档位是"选择演什么"，数值是"演得多熟/观众多固化"
- **技能**：游戏力、歌唱力、杂谈力、整活力、声音等（各分等级）+ 知识面（深度/广度，决定素材利用率）
- **关系**：与每个朋友的好感、信任、依赖（各自独立）

### 4.7 跨场数值（不上常驻条）

- **粉丝构成向量**（见 4.8）
- **炎上值**：跨场累计，压力源放大器
- **契约进度**：债务余额、6 期判定完成情况

### 4.8 粉丝构成向量（五类互斥）

**结构**：`路人 R / 男粉 M / 女粉 W / 核心粉 C / 黑粉 B`，归一化百分比：R+M+W+C+B = 100%。路人无性别；核心粉、黑粉从男女粉转化而来。

**每场直播后的变动流程：**

1. **基础扰动 Δ** = Σ(行为卡 fanBias) + 素材 affinity 修正 + 事故修正（事故 → B↑、R↓）
2. **新增路人** = 热度 H × 转化率；转化率 = base × (1 − 0.8 × (C+B))
   - **核心粉与黑粉占比越高，新粉越难流入 —— "观众固化"的数值落地**
3. **路人 → 男女粉**：按内容质量留存系数
4. **男女粉 → 核心粉**：打赏/舰长事件概率转化（核心粉 = 金主）
5. **黑粉**：增 = 炎上量 × 黑化系数；每场自然衰减 10%（淡出，但节奏事件可复活）
6. **归一化**

**反哺（让向量真正影响决策）：**

- **变现**：收益 = 热度 × (0.3R + 0.6(M+W) + 1.6C − 0.5B)——核心粉是金主，"转化核心粉"是经营目标
- **破圈**：新粉转化率 ∝ R 占比。长期演同一人设 → 结构偏科 → 破圈停滞
- **舆论**：B > 15% → 炎上概率翻倍、事故放大，并进入状态快照（LLM 演"黑粉蠢动的弹幕氛围"）
- **换人设成本**：切换档位时，M/W 结构 ×0.8（脱粉 20%），且 C×0.3 转化为 B（脱粉回踩）
  - 这收紧了核心张力：**专精 → 熟练度↑、变现↑，但固化 → 增长停滞；多元 → 增长快，但变现差**
- **演出语境**：构成向量作为状态快照的一部分给 LLM，LLM 只演"氛围"，不演有名有姓的粉丝个体——**唯一例外：榜一鹿铃**（见 8.5，具名角色，单独人物卡）

**显示简化**：一根五段条形图 + 总粉丝数 + 一句提示（如"黑粉扎堆"/"观众结构固化"），玩家看趋势，不读数字。

## 5. 卡牌系统

### 5.1 总览（90 张）

- **方向树 ×5**：游戏 / ASMR / 杂谈 / 唱见 / 整活，每棵 8~12 张
- **通用树 15~20 张**：打招呼、结束语、情绪反应（如"色气的打招呼"）
- **技能 5~8 个 ×3 级**：声音、话术、反应、体力等（被动，与卡牌分离）
- 解锁期分层：基础卡（前 15 天）/ 进阶卡（30 天后）/ 王牌卡（60 天后）
- **槽位**：初始 2，每升 2 级 +1，上限 5~6

### 5.2 卡牌字段

```json
{
  "id": "greet_sultry_01",
  "tree": "universal_greet",
  "tier": 1,
  "title": "色气的打招呼",
  "description": "玩家可见的描述文字。",
  "slots": 1,
  "unlock": { "exp": 300 },
  "effect": {
    "multiplier": 1.3,
    "fanBias": { "male": 0.12, "female": -0.08 },
    "risk": 0.1,
    "stressCost": 5,
    "condition": "开场节拍",
    "combo": [
      { "withTag": "persona_sultry", "multiplier": 1.8 },
      { "withTag": "material_moe",   "multiplier": 0.8 }
    ]
  },
  "tags": ["打招呼", "色气"],
  "prompt": "<string：导演指示片段，措辞待 prompt 工程设计>"
}
```

**要点：**

- **效果数值只给代码读**；连击判定全部在代码侧（tag 匹配 + 数值运算）
- **prompt 是 plain string**，只是最终 prompt 的**片段之一**；最终 prompt 是多个片段 + 状态快照的拼接（人设.prompt + 行为卡.prompt + 素材.prompt + 快照 → 一条 string）
- **prompt 工程尚未设计**：谁的视角、谁是主语（主播/导演引擎）、如何衔接，均未定；本阶段不预设任何 prompt 措辞
- prompt 只写"怎么演"，不写"演什么对象"（对象由素材提供）

### 5.3 卡牌收益结构三分法

- **涨粉卡**：收益低、粉丝结构扩张，对冲固化
- **变现卡**：打赏流，但消耗精神多
- **事故卡**：高风险高回报，节目效果引擎

### 5.4 EXP 与解锁

- EXP 来源：打工、打游戏（练习）、约会（朋友事件）、直播、日常事件
- 等级 → 解锁卡牌节点 + 增加卡槽

## 6. 素材系统

### 6.1 核心答案：有含量

素材**既不是一次性，也不是无限**，而是"**有含量（depth）**"：

- 含量是资源池。如一款游戏含量 4；每场直播按类型消耗：杂谈耗 0.5~1，游戏实况耗 1~2
- 含量耗尽 → 素材变"陈旧"：还能引用，但直播质量下降（观众："主播又在水"）

### 6.2 三个属性

| 属性 | 作用 |
|---|---|
| 含量 depth | 还能喂几场直播 |
| 进度 progress | 连续型素材的进度指针；每次游戏实况推进一章 |
| 衰减 freshness | 首发热度加成随场次递减；旧素材变"情怀素材"（倍率低、核心粉偏好高） |

**关于重复利用与 LLM 发挥**：重复的根源不是"用了第二次"，而是"没有新输入"。进度 + 上一场摘要（从体验记忆取）= 新输入 → 系列直播反而越播越有味道（callback："上次卡墙里那只 BOSS"）。

### 6.3 两种类型

| 类型 | 例子 | 经济角色 |
|---|---|---|
| 连续型 | Sbeam 游戏、追新番（带进度+含量） | 贵、高价值、需投入时间；对应游戏实况/唱见 |
| 消耗型 | 谷子开箱、限时活动、论坛热梗 | 便宜、即时、一次性；对应杂谈/整活 |

### 6.4 获取管道（稳定供给）

- **购买流（确定性）**：Sbeam 商店、周边店——钱的出口，防金钱溢出
- **白嫖/事件流（半随机）**：限免、朋友安利、论坛热梗、外出事件——时间的出口
- **轮换池**：商店固定上架 + 季节性活动轮换，保证后期供给
- **技能挂接**：知识面（L1 数值）提高素材利用率——技能是素材的放大器

### 6.5 素材即内容卡

素材与卡牌**共用同一套字段**（title / description / effect / prompt），额外字段：`depth / progress / freshness / affinity`（affinity = 喂给哪类直播）。数据模型上只有一种东西：**内容卡**。

**待拍板**：① 含量粒度按"场次"计（每场固定耗 1~2 格）是否够；② 素材 prompt 来源：核心素材手写保质感，其余 LLM 生成初稿 + 人工审核（是否接受混排）。

## 7. 直播系统

### 7.1 三拍制（待测试）

演出结构：**开头 / 中间 / 结尾**。最终形态（每拍内容、长度、快进交互）需长期测试后定稿，当前不深入。

### 7.2 预结算架构（关键）

- **开播瞬间，代码先掷完整场结果**：热度、收益、事故、粉丝变动全部由代码预结算
- **LLM 只是照既定结果演绎**——它不知道结果，只负责演出
- 演出**不反写核心数值**（纯装饰）；LLM 输出标签仅写回体验记忆与叙事层（下播日记、弹幕氛围）

由此得到的性质：

- **跳过/快进永远安全**：结算已存在，跳过演出 = 丢弃装饰、立刻结算，同时省 token
- **断网/失败有兜底**：数值不依赖 LLM

### 7.3 流水线生成（表现层优化）

逐拍生成：玩家观看第 N 拍 AVG 演出时，后台生成第 N+1 拍——感知延迟被阅读时间吞掉。属于表现层优化，后期实现。

### 7.4 事前安排 / 事后处理

- **连麦朋友** = 准备阶段的一个行动（"今晚邀请网友连麦"），朋友状态/好感影响演出效果——朋友系统接入直播的唯一通道
- **黑粉/炎上无法在直播中救场** → 下播后的**舆情事件**：2~3 个菜单选项（发动态回应 / 冷处理 / 装死 / 道歉），影响粉丝构成与压力

## 8. 角色系统

### 8.1 命名规则（三条）

1. **名字不挂钩身份**（"周建国不建国"）：宅女不代表懒，王牌主播不代表飒——名字就是名字，意义由行为赋予
2. **二次元主角感**：稀有姓 + 自然物象/意象字；不落"林晚晚"式网文流水线名，也不落"王芳"式朴实名——玩家先记住她，才能代入她
3. **Vtuber 网名与真名分离**：网名由玩家在开局填表时输入，进入 LLM 快照——直播语境观众只以网名称呼；真名只出现在聊天软件、合同、朋友对话

### 8.2 角色总表

| 角色 | 名字 | 身份 | 功能位 |
|---|---|---|---|
| 女主角 | **阮云柚** | 23 岁家里蹲宅女 | 玩家操纵角色 |
| 青梅 | **陆鸢鸢** | 23 岁，Vtuber 公司王牌主播 | 压力源 + 情感锚点 + 坏结局收留者 |
| 地雷妹 | **鹿铃** | 24 岁富家女 | 金钱/素材源 + 高压线 + 榜一（观众中唯一具名角色） |

### 8.3 阮云柚（女主角）

- 23 岁，独居小屋，毕业即家里蹲，蹲了三年
- 性格底色：怕生、嘴硬、内心戏极多、对喜欢的东西有惊人热情（记声优生日、背轻改动画删减剧情）

### 8.4 陆鸢鸢（青梅）

- 外观：**潇洒干练的短发女孩（注意：不是假小子）**

  - LLM 为她**单独维护人物卡**；直播中她的 SC 由她的人格驱动（甜中带刺："柚柚~下播陪我去吃冰"），观众吃瓜弹幕是天然节目效果

## 9. 开局序章

1. **游戏开始先弹出聊天软件**（而非主菜单）
2. 青梅说明情况，发送**入职信息填写链接**
3. 玩家点击链接，为 Vtuber 形象**起网名**——第一个创作行为，人设系统埋种子（网名进入 LLM 快照，直播语境使用）
4. 填写报名信息/简历：无业 3 年、下午 3 点起、特长（记得所有当季声优生日、熟背轻改动画删减剧情）、学历（肄业，原因：追番）——**简历字段即人物塑造**，玩家笑着了解女主是废物
5. 填写完毕发给青梅 → **图穷匕见**：违约金数字 + 直播义务条款弹出，喜剧氛围瞬间转压力——全游戏第一个情绪拐点
6. 第一天教程：用一场**试播**教学直播 UI——无合约压力、结果宽松

## 11. LLM 架构原则

1. **数值是真相，LLM 是表达**：核心结果代码预结算；LLM 输出标签仅写回体验记忆与叙事层
2. **状态快照**：每节拍生成前给 LLM 一份快照 = 人设档位 + 熟练度 + 相关技能 + **三属性当前值（压力/宅欲/孤独）** + 本场素材 + 关系上下文 + 粉丝构成（观众氛围）
3. **三层记忆**：
   - 事实账本（代码存）：钱、合约进度、粉丝数、大事——LLM 无权改
   - 关系记忆（代码存）：谁是谁——朋友、榜一鹿铃（具名）、房管（半边界）
   - 体验记忆（LLM 摘要）：每场直播后压成摘要，下播日记/对话时注入
4. **成本控制**：按节拍短生成（1~2 秒/拍）；开场白缓存；弹幕 = 模板池 + LLM 点缀混合；跳过演出省 token

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| 一致性（LLM 遗忘/篡改事实） | 事实账本 + 预结算 + 关系记忆代码化 |
| 成本 | 短节拍生成、跳过省 token、弹幕模板混合 |
| 重复性 | 素材含量/进度/衰减 + 事件库 + 状态变量注入 |
| 表现力不足 | 前端氛围（弹幕流/SC/立绘差分）承担质感，文本短 |
| 决策负担 | 常驻条仅 3 根（压力/宅欲/孤独）；粉丝向量只显示趋势不显示数字 |
