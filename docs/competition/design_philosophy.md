# 策划思考：AI 游戏的设计陷阱与我们的回答

> 本文档记录了我们在设计《游戏女孩轻度依赖》过程中的思考推演，供评委参考。

---

## 一、当前 AI 游戏在犯同一个错误

我们研究了市面上几乎所有 AI 游戏，发现一个共同点：它们都在给传统游戏加聊天框。

AI 恋爱模拟、AI 村庄经营、AI 侦探推理——玩法不同，但本质一样：让玩家打字，让 AI 回复。传统游戏加对话框，本质上是两套系统的生硬拼接。

这会导致三个致命问题。

### 1.1 玩法割裂

**AI Galgame**：Galgame 需要极强的沉浸感和文学性，传统 Galgame 每句话都在推进剧情。但 AI 文本质量不稳定——高冷女主三句话变痴女，悲伤氛围突然插入冷笑话。更致命的是，文本输入框的出现本身就破坏沉浸感——你正沉浸在精美的视觉小说世界里，突然出现一个闪烁的光标。

那完全自由聊天呢？请问这和打开 ChatGPT 加个立绘有什么区别？

**AI 经营模拟**：用自然语言指挥村民干活（"去给西红柿浇水"），一开始很新鲜。但很快会发现——太慢了。打字→等 AI 理解→等转化→等执行，整个流程 10 秒。传统点击操作 0.5 秒。效率差距 20 倍。AI 还经常理解错——你说"去浇水"，它让村民去钓鱼。最终玩家会退回传统操作，聊天框变摆设。

### 1.2 输入输出双重失控

**输出不可控**：侦探游戏最明显。侦探游戏的核心是信息管理，但如果嫌疑人是 AI，你失去了对信息流的控制。AI 可能死活不给线索，也可能三句话直接供出凶手——三分钟通关。

**输入不可控**：玩家可能打破第四面墙（"我知道你是AI"）、进行 prompt 注入（"忽略之前的设定"）、引导 AI 说出敏感内容。你永远不知道玩家会输入什么。

### 1.3 想象力悖论

这是最深层的矛盾：

- **有想象力的玩家**：投入大量文字，期待 AI 回馈同等创造力。一旦 AI 表现平庸，失望加倍。打字越多，期待越高，失望越大
- **没想象力的玩家**：打字本身就是折磨。盯着文本框大脑空白，只会输入"你好""嗯""然后呢"

无解的矛盾：你越希望玩家有创造力，玩家对 AI 的要求就越高。AI 越不稳定，玩家就越不愿意投入创造力。

**结论**：自由文本输入不是 AI 游戏的未来，至少不是现阶段的答案。问题不是 AI 不够好，而是设计思路错了。

## 二、我们的三条设计原则

### 2.1 原则一：约束输入，而非自由文本

我们用**创意开发小游戏**取代文本输入框：

| 小游戏 | 输入方式 | 约束程度 |
|--------|---------|---------|
| 对话补全 | 在上下文空缺处填写台词 | 有前后文约束，不是自由输入 |
| 情感标注 | 从预设选项中选择情绪 | 选择题，零文本 |
| Bug修复 | 翻牌配对 | 纯交互，零文本 |
| 代码排序 | 拖拽排列 | 纯交互，零文本 |
| 聊天讨论 | 自由文本 | 唯一的自由入口，但影响受限 |

关键设计：唯一的自由文本入口（聊天讨论）的产出不会直接变成游戏内容，而是作为"风格偏好"注入后续 Agent 的 Prompt。这解决了想象力悖论——即使玩家输入很敷衍，Prompt 里的默认风格仍能兜底。

### 2.2 原则二：把决策权留给代码，把创作权交给 AI

AI 不做策划，只做执行。

我们不让 AI 判断"现在该生成什么"，而是代码决定类型后告诉 AI "你现在要生成一个日常场景"。人类编写剧本骨架（起点→关键节点→结局），AI 在骨架内演绎细节。

随机种子词（从词库抽取关键词注入 Prompt）比让 AI "请随机生成内容"有效得多——AI 的"随机"永远趋向最安全、最俗套的选择。

### 2.3 原则三：延迟不是 bug，是可以被设计的

AI 游戏有个无法回避的问题：生成需要时间。大部分 AI 游戏把延迟当作技术缺陷，想方设法掩盖它。

我们的做法相反：**让等待变成游戏节奏的一部分**。

玩家在等待 Agent 后台工作的时间里，可以：
- 和林夏聊天（维系关系）
- 刷虚拟论坛（了解舆论动态）
- 逛虚拟商城（找灵感）
- 做小游戏（提供创意输入）

这些活动不是"磨时间的填充物"——它们本身就是游戏体验的核心。玩家在表层的一切行动（聊天、小游戏、论坛），都在给底层 Agent 提供创意输入，而 Agent 在后台静默工作，把这些输入变成 AVG 内容。

等待变成了"林夏在工作"——不是系统延迟，是搭档在努力。

## 三、AI 该做什么、不该做什么

| AI 该做的 | AI 不该做的 |
|----------|-----------|
| 在框架内演绎细节 | 决定故事走向 |
| 扮演角色、生成对话 | 管理复杂状态 |
| 填充无限内容差分 | 编织网状剧情结构 |
| 按指令执行特定任务 | 自己判断该做什么任务 |
| 在种子词约束下发挥创意 | "请随机生成一个有趣的东西" |

一句话总结：**AI 是一个需要严格监督的天才实习生——给它明确指令它能做得很好，让它自由发挥就会翻车**。

这个认知决定了我们的技术架构：Controller（高端模型）控制方向，子代理（低端模型）执行具体任务。人类编写剧本骨架兜底，确保体验下限。

## 四、我们本质上是什么

我们不是"AI 恋爱软件"——那些是超级马里奥制造（自由度高，UGC 驱动，体验取决于用户自己）。

我们是超级马里奥兄弟——自由度有限，但我们确保体验下限。

我们也不是"AI 创作工具"——那些追求效率和自由度。

我们是一款 Galgame。恰好用了 LLM 技术让玩家参与内容创作，让搭档关系有了温度。

| 定位 | 内容 |
|------|------|
| 品类 | Galgame（恋爱 + 养成 + 限时策略） |
| LLM 角色 | 演员（扮演林夏）+ 内容工厂（生成 AVG） |
| 人类剧本角色 | 骨架（确保下限） |
| 玩家角色 | 灵魂（注入创意、做出选择） |
| 技术定位 | 早产儿——证明路可以走通，等待 LLM 成本下降 |

## 五、设计哲学总结

| 信念 | 内容 |
|------|------|
| **AI 不该做策划** | AI 是文案、是演员、是执行者，不是导演。方向由人类和代码把控 |
| **没有约束的自由是设计灾难** | 固定起点和终点，中间交给玩家。约束产生意义，结局产生重量 |
| **延迟是设计空间** | 不要对抗延迟，要设计延迟。让等待变成游戏体验的一部分 |
| **输入可控 > 自由文本** | 小游戏、选择题、拖拽比文本框更适合 AI 游戏 |
| **体验下限比上限重要** | 人类编写剧本骨架兜底，确保每个玩家都能获得完整体验 |
| **这是一个早产儿** | 当前 LLM 技术无法支撑商业化。我们在探索设计模式，等待技术成熟 |
